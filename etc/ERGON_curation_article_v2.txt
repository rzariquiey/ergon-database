ERGON: A Curated Cross-Linguistic Database of Ergative Alignment Features
Data Curation Methodology and Repository Description
Abstract
This paper describes the data curation workflow applied to ERGON, a cross-linguistic database documenting grammatical features related to ergative alignment across a typologically diverse sample of the world’s languages. The raw data, collected from published grammatical descriptions, consisted of 195 language fichas distributed across Excel spreadsheets and CSV files, accompanied by 222 reference PDFs. The curation process encompassed: (i) file extraction and normalization; (ii) systematic addition of language-level metadata (Glottolog code, language name, genealogical family) to all tabular records; (iii) standardization of filenames to Glottolog codes; (iv) detection and classification of data quality issues; (v) reorganization of the dataset into validated and pending-review subsets; (vi) generation of curated records for all 195 fichas, each carrying a provenance-preserving curation flag, a language-level annotation summary, and a final_value field consolidating original and curated values into a single analysis-ready column; and (vii) feature-level second-coder verification of all coded values against primary source PDFs for the 22 fichas in the pending-review subset, yielding approximately 70 individual corrections; and (viii) a reliability sample verification of six unchanged fichas drawn from six distinct genealogical groups, confirming that all 144 sampled feature values were correctly annotated without modification. A total of 35 files were identified as requiring correction due to glottocode misassignment, unresolved language identification, or template contamination. All curation scripts are made available as a companion repository. The resulting dataset provides a standardized, machine-readable resource for the cross-linguistic study of ergativity.
Keywords: ergativity, cross-linguistic database, data curation, Glottolog, language typology, linguistic data management

1. Introduction
Ergativity is a grammatical phenomenon in which the subject of an intransitive verb is treated like the patient (rather than the agent) of a transitive verb, creating an alignment pattern that stands in typological contrast to the nominative-accusative pattern predominant in European languages. Cross-linguistic research on ergativity has grown substantially over the past decades (Dixon 1979, 1994; Aldridge 2008; Laka 2006; Malchukov & Spencer 2009), yet structured, machine-readable resources aggregating fine-grained ergative features across large language samples remain scarce.
ERGON was conceived to address this gap. The database systematically documents a set of binary and multi-valued features related to ergative alignment — including flagging, indexing, case morphology, split ergativity, and related phenomena — for a typologically and genealogically diverse sample of the world's languages. Each language is represented by an individual data sheet (ficha) encoding feature values together with source references drawn from published grammars, grammatical sketches, and descriptive monographs.
This paper documents the systematic data curation process applied to the ERGON dataset prior to its first public release. Curation was necessary because the raw data had been collected incrementally by multiple contributors using template-based spreadsheets, resulting in a range of inconsistencies: missing or incorrect language-level metadata, non-standard filenames, template contamination, and in several cases, misassignment of Glottolog identifiers to language files. Section 2 describes the raw data format and sources. Section 3 details each curation step. Section 4 presents the error taxonomy developed during curation and the quality metrics of the final dataset. Section 5 describes the companion script repository. Section 6 concludes.
2. Raw Data: Format and Sources
2.1 File Format and Structure
Prior to curation, the ERGON data were stored as a collection of individually-named spreadsheet files (fichas), one per language, distributed across two ZIP archives. The internal folder structure of each archive followed a consistent pattern: each language was assigned a top-level folder named after its Glottolog code (Hammarström et al. 2024), and that folder contained the corresponding ficha and, in most cases, the PDF of the primary reference grammar used as the source.
Fichas were provided in two formats: Microsoft Excel (.xlsx) and comma-separated values (.csv). All fichas followed a common column schema consisting of five fields: Ergon_ID (a unique feature identifier), Feature (a descriptive label for the grammatical feature under investigation), Value (a binary or categorical coding), Source (bibliographic reference with page numbers), and Comment (free-text annotations and glossed examples). No language-level metadata — language name, genealogical family, or Glottolog code — was included within the ficha files themselves; this information was encoded only in the folder and filename structure.
2.2 Coverage
After extraction from the source archives, the raw dataset comprised 157 Excel fichas, 38 CSV fichas, and 222 PDF reference documents, covering a total of 195 languages. The language sample spans all major macro-areas and genealogical groups, with particularly dense coverage of Trans-Himalayan, Austronesian, Pama-Nyungan, and Trans-New Guinea families, consistent with the typological literature on ergativity.
3. Curation Methodology
The curation pipeline was implemented entirely in Python 3, using the openpyxl library for Excel manipulation, the csv standard library module for CSV processing, the zipfile module for archive extraction, and python-docx for report generation. All scripts are described in Section 5 and provided in the companion repository. The pipeline comprised six main stages, described below.
3.1 File Extraction and Normalization
The source ZIP archives were extracted using Python's zipfile module rather than system-level utilities, in order to handle large archives reliably and avoid timeout issues with deeply nested directory structures. All files — Excel fichas, CSV fichas, and reference PDFs — were extracted into a single flat directory (fichas_ergon/), discarding the intermediate folder hierarchy. This normalization step allowed all subsequent operations to be applied uniformly across file types without path traversal logic.
Following extraction, all Excel and CSV files were renamed so that the filename consisted exclusively of the language's Glottolog code (e.g., ship1254.xlsx for Shipibo-Konibo). Three files had non-standard names — including one file whose stem was a descriptive title rather than a code — and were renamed after manual identification of the target language. Reference PDFs were similarly renamed by prepending the language's Glottolog code to the original filename (e.g., ship1254_valenzuela_shipibo2003.pdf), enabling unambiguous association of each grammar with its corresponding ficha.
3.2 Addition of Language-Level Metadata
Because ERGON fichas contained no within-file language identification, a critical curation step consisted of adding three metadata columns — Glottocode, Language, and Family — as the first three columns of every ficha, with values repeated on each data row. This design ensures that the files are self-contained and can be queried or concatenated without reference to external lookup tables.
Language names and genealogical family assignments were determined through a combination of (i) Glottolog entries for each code, (ii) the filenames of the associated reference PDFs, which typically encode author name, language, and year of publication, and (iii) direct inspection of source ficha content where ambiguity remained. Metadata was added to Excel fichas using openpyxl (column insertion at position 1) and to CSV fichas by prepending the three columns to the header and each data row during a read-write pass.
Given the size of the dataset (195 languages), metadata assignment was performed in two batches corresponding to the two source archives, using a curated lookup dictionary (GLOTTOLOG) mapping each Glottolog code to a (language name, family) tuple. Languages that could not be confidently identified at the time of initial processing were flagged as VERIFICAR (see Section 4).
3.3 Error Detection and Classification
A systematic review of all fichas identified three categories of data quality issues, described here as Type 1, Type 2, and Type 3 errors.
Type 1 errors (incorrect initial metadata) affected six Excel fichas in which the Glottolog code present in the filename corresponded to a different language than the one actually documented in the file. This was established by cross-referencing the associated PDF filename and, where necessary, inspecting the ficha content. Affected files included cases where superficially similar Glottolog codes had been confused (e.g., a code initially interpreted as referring to a South Asian language that actually identifies a Greenlandic one) as well as cases of apparent glottocode misassignment by the original data contributor (e.g., a file labeled with the code for Nuclear Malagasy whose content and reference grammar were unambiguously about Georgian). Metadata was corrected in all six cases, and the proposed Glottolog code for the actual documented language is recorded in the filename.
Type 2 errors (unresolved language identity, subsequently resolved) affected sixteen fichas that had initially been flagged as VERIFICAR because the target language could not be identified from the Glottolog code alone. In all sixteen cases, inspection of the associated PDF filename provided sufficient information to determine the language, its correct name, and its genealogical affiliation. Metadata was updated accordingly.
Type 3 errors (critical unresolved issues) affected four files for which the discrepancy between the assigned Glottolog code and the apparent language content could not be resolved without external verification. These include a ficha whose internal sheet name references a different language (Dadibi) than the one implied by the filename; a ficha labeled with the Hualapai code whose associated grammar is a description of Lisu; a ficha with an unidentifiable source reference (Nitsch 2009); and a CSV ficha whose grammar PDF documents Migili but whose assigned code corresponds to a distinct Oceanic language. These files remain in the pending-review subset pending manual inspection by domain experts.
An additional category of template contamination was identified in seven fichas whose internal Excel sheet names retained the identifier of the template language from which they had been copied (either cent2127 — Central Alaskan Yupik — or dadi1250 — Dadibi), rather than being updated to reflect the actual target language. Since the file content and Glottolog codes were verified as correct in six of these seven cases, only the ficha with the most severe content discrepancy (dech1234) was retained in the pending-review subset; the remaining six were moved to the validated subset after confirmation.
3.4 File Renaming Convention for Flagged Files
All fichas identified as having a Glottolog code discrepancy — whether resolved or unresolved — were renamed following the convention X_[initial_code]=[proposed_code], where X serves as a visual flag for files requiring attention, initial_code is the Glottolog code present in the original filename, and proposed_code is the code identified as corresponding to the actual documented language. When the initial code was confirmed as correct (no misassignment, only a labeling ambiguity), the two sides of the equals sign are identical (e.g., X_kala1399=kala1399.xlsx). This convention preserves full traceability of the original assignment while enabling rapid visual identification of files requiring curator attention.
3.5 Dataset Partitioning
Following error classification and renaming, all files (Excel fichas, CSV fichas, and PDF grammars) were partitioned into two subsets within the fichas_ergon/ directory: correctos/ (validated files) and por_revisar/ (pending-review files). The validated subset contains 169 CSV data files and 191 PDF grammars. The pending-review subset contains 33 flagged data files (32 Excel and 1 CSV) and 31 PDF grammars. This partitioning ensures that the validated data can be used immediately for analysis while the pending files remain accessible and clearly delimited.
3.6 Format Standardization
As a final step, all Excel fichas in the validated subset were converted to CSV format using openpyxl for reading and Python’s csv module for writing, producing a uniform, software-independent tabular format across the entire validated dataset. UTF-8 encoding was used throughout. The original Excel files are retained in the repository as an archival record.
3.7 Generation of Curated Records
For every ficha in the dataset — both in the correctos/ and non_ergative/ subsets — a corresponding curated record was generated as a separate CSV file following the naming convention [glottocode]_curated.csv. These curated files share the column schema of the original fichas but add three curation-specific fields. The first is a curated flag that records whether the original value was modified: it takes the value 1 when the original value was corrected to 1, the value 0 when corrected to 0, and is left blank when the original value was confirmed unchanged. The second is a curated_comment field providing a language-level summary of the curation decisions, source verification outcomes, and any corrections applied to that ficha. The third is a final_value field, which consolidates original and curated values into a single analysis-ready column: for each feature row, final_value takes the curated value when a correction was recorded, and the original Value field otherwise. This field constitutes the definitive coding to be used for all downstream typological analyses, as it reflects the most current and verified state of each annotation regardless of whether a correction was applied. This design ensures that original annotations and curated annotations are kept in separate files, preserving full provenance: the original ficha documents what was coded before curation, and the _curated.csv file documents the post-curation state together with the reasoning behind each modification. The generation of curated records was applied uniformly to all fichas in the dataset, yielding a total of 196 _curated.csv files.
3.8 Feature-Level Verification by a Second Coder
Beyond the generation of curated records for all fichas (Section 3.7), the 22 fichas that had been placed in the pending-review subset were additionally subjected to systematic feature-level verification by a second coder. This phase addressed two complementary quality concerns: the resolution of features annotated as uncertain (‘?’), and the independent verification of all coded values — including zeros and ones — against the relevant passages in the primary source PDFs. Crucially, this second pass did not restrict itself to uncertain annotations but re-examined every coded value, since errors in definite codings are typically harder to detect by automated means and can persist unnoticed through purely structural curation steps.
Given the volume of material to be verified — up to 24 feature values per language across 22 fichas, each requiring consultation of the corresponding reference grammar — the verification workflow was designed to optimize throughput through parallelization. Multiple verification passes were dispatched concurrently, each assigned to a single language and tasked with: (i) locating the relevant sections in the source grammar; (ii) confirming, correcting, or revising each feature value against textual evidence; and (iii) generating structured field-level annotations documenting page references and justifications for each decision. Concurrent execution of multiple independent passes substantially reduced total verification time compared to a sequential workflow while preserving the independence of each individual verification. Each pass operated exclusively on the source PDF and the existing ficha, without access to the results of other concurrent passes, ensuring that confirmations and corrections reflected independent readings of the evidence.
A total of 22 language fichas were submitted to second-coder review. Of these, 21 could be verified against their source PDFs; one ficha (Ganai, gana1278, Pama-Nyungan) could not be verified due to a corrupted cross-reference table in the PDF file that rendered the source unreadable by any standard text-extraction tool. Across the 21 verifiable fichas, approximately 70 individual feature values were modified, spanning corrections in both directions (0→1 and 1→0), resolutions of uncertain values (‘?’→0 or 1), and conversions of previously definite values to uncertain status in cases where the source evidence was found insufficient to support the original coding. In total, 15 of the 21 verifiable fichas required at least one modification to a coded value, while 6 fichas had all existing values confirmed without change.
The most consequential corrections included the following. First, the systematic reannotation of Momu-Fas (fass1245, Trans-New Guinea): 24 feature values were corrected from spurious ergative codings to 0 after PDF verification established that the clitic =m, analyzed as an ergative marker in the original ficha, is an object/oblique marker in a nominative-accusative system (Honeyman 2016). The file was reclassified to a dedicated non_ergative/ subdirectory. Second, both Lisu fichas (hual1240 and dech1234) had misidentified the morpheme nɛ³³ as the ergative/agentive and instrumental case marker (yielding GB409_24=1 for both fichas). Consultation of Yu (2007) confirmed that nɛ³³ is the locative marker in the Dechang dialect and a demonstrative in other varieties; the actual agentive marker is le³³ and the instrumental is du³³. GB409_24 was corrected to 0 for both fichas, and GB409_16 was additionally corrected from 1 to 0 for dech1234, where the active-stative conditioning had been misattributed to topicality. Third, for Georgian (nucl1302), feature GB409_15 (ergative alignment with non-agentive A) was corrected from 0 to 1 following identification of five examples in Hewitt (1990: 187–189) of inanimate, non-volitional subjects taking the Series II ergative case (e.g., ‘the sun dried the field’, ‘the sweat penetrated the shirt’). Fourth, three features in Kalaallisut (kala1399) — GB409_1, GB409_2, and GB409_3 — were corrected from 1 to 0, reflecting that the absolutive is zero-marked in that language and that first- and second-person pronouns have a single ‘direct case’ form with no morphological distinction between absolutive and ergative functions. Fifth, feature GB409_16 (ergative alignment with topical A) was corrected from 1 to 0 for Nêlêmwa (bala1316), following Bril (2002: §3.7.1), which states explicitly that a thematized transitive subject obligatorily appears without the agent markers an or ru. Beyond these major corrections, 8 previously uncertain values in Wobzi Khroskyabs (guan1266) and 11 in Kalaallisut (kala1399) were resolved to definite values through PDF evidence.
The results of the second-coder review are recorded in the curated_comment field of each affected ficha row, which documents the specific textual evidence — including page references and, where applicable, glossed examples — supporting the modification. This field is absent from the original data and constitutes a curation-added layer of documentation that enables future users to assess and if necessary revisit individual coding decisions.
3.9 Reliability Sampling of Unchanged Fichas
The second-coder review described in Section 3.8 targeted fichas that had been flagged as pending review. A complementary question is whether fichas that passed through the curation pipeline without any modifications are equally reliable. Of the 195 fichas in the dataset, 158 carry no curated changes in their _curated.csv file, meaning that all original coded values were confirmed unchanged. To assess the reliability of this subset, a random sample of six fichas was drawn from the 148 unchanged fichas for which a reference PDF was available, spanning six distinct genealogical groupings: Basque (basq1248, Language isolate), Bantawa (bant1281, Trans-Himalayan), Äiwoo (ayiw1239, Austronesian), Adnyamathanha (adny1235, Pama-Nyungan), Avar (awar1248, Nakh-Daghestanian), and Aleut (aleu1260, Eskimo-Aleut). For each ficha, all 24 GB409 feature values were independently verified against the corresponding passage in the primary source grammar, following the same protocol as Section 3.8.
All 144 feature values across the six fichas were confirmed as correctly annotated. No value corrections were required. One minor bibliographic error was identified and corrected: the Source field for GB409_5 in the Äiwoo ficha (ayiw1239) cited Dunn et al. (2002: 35, 52), but page 35 of that source does not contain Äiwoo data; the citation was corrected to Dunn et al. (2002: 52). The verification also produced several substantive observations that, while not requiring value corrections, contextualize the annotations for future users. For Aleut (aleu1260), GB409_5=1 is correct but the ergative (relative case –m) on full NPs is conditioned by object-drop: when a full NP object is overtly present, the transitive subject takes the absolutive rather than the ergative, a pattern consistent with the broader pronominality split documented under GB409_22. For Bantawa (bant1281), the absence of a distinct instrumental case (supporting GB409_24=1) is explicitly stated by Doornenbal (2009: 73). For Avar (awar1248), the grammar labels the relevant clitic as “ablative” but its distribution as both transitive subject marker and instrument marker confirms the ergative/instrumental syncretism annotated under GB409_24. These results support the reliability of the unchanged ficha subset and suggest that the original coding was generally accurate for fichas that did not exhibit the structural anomalies targeted in the pending-review classification.

6. Discussion and Limitations
The curation workflow described here was designed to be transparent and reproducible: all decisions are encoded in the scripts and lookup dictionaries, and all flagged files retain their original codes in the filename so that the full provenance chain is traceable. Nevertheless, several limitations deserve acknowledgment.
First, Glottolog code verification relied on a combination of training knowledge and PDF filename heuristics rather than programmatic querying of the Glottolog API. While this approach proved effective for the majority of the dataset, the seven entries marked [ESTIMAR] in the renaming scripts carry proposed codes that should be verified against the current Glottolog catalog before the dataset is published. Future curation workflows should incorporate direct API calls to glottolog.org to automate this step.
Second, the structural error detection procedure described in Section 3.3 was based on surface-level evidence — filename patterns, sheet names, and PDF filenames — rather than on content-level validation of the coded feature values. The feature-level second-coder verification described in Section 3.7 addresses this limitation for the 21 fichas that could be verified, and the results confirm that content-level errors can be substantial and typologically consequential even in fichas that pass all structural checks. The one ficha that could not be verified (Ganai, gana1278) retains its original annotations and should be treated as unvalidated at the content level; obtaining a readable copy of Fesl (1985) and subjecting this ficha to the same verification procedure is recommended before the dataset is used for analyses that include this language.
Third, the four Type 3 cases and the [ESTIMAR] entries represent an irreducible residual uncertainty that cannot be resolved through automated means alone. These cases are clearly delimited in the dataset structure and require attention from expert linguists with knowledge of the relevant language areas.
7. Conclusions
This paper has described the systematic data curation process applied to the ERGON cross-linguistic database on ergativity. Starting from a heterogeneous collection of template-based spreadsheets distributed across ZIP archives, the curation pipeline produced a normalized, metadata-enriched, and quality-classified dataset suitable for computational analysis. The key outputs are: (i) a validated subset of 169 language fichas in uniform CSV format, each carrying within-file metadata; (ii) a pending-review subset of 33 fichas with documented discrepancies; (iii) a companion repository of six reproducible curation scripts; and (iv) a systematic error taxonomy documenting 36 individual data quality issues.
The workflow described here is generalizable to other collection-based linguistic databases assembled through distributed, template-driven data entry. The combination of Glottolog-based file identification, PDF cross-referencing for ambiguous cases, and a transparent naming convention for flagged files provides a reusable curation framework for similar typological datasets.
